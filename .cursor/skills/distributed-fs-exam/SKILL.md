## 一、引言与基本概念（Part 1）

### 1.1 定义与特点
> 待补充：分布式文件系统的定义、核心特点（透明性/可扩展/高可用/容错/共享等）、与单机/集中式文件系统的区别。

### 1.2 发展历程及现状

#### 发展历程
- **早期**：分布式文件系统主要关注**高可用性**和**可扩展的存储服务**。
- **现代**：随互联网和云计算快速发展，转向**数据处理与分析能力**，并注重**与其他大数据技术的融合**。
- 演进主线：从「单纯存储」→「存储 + 处理/分析 + 大数据融合」。

#### 现状
- **应用领域**：云计算、大数据处理、高性能计算（HPC）等。
- **定位**：构建大规模数据存储与处理系统的**重要基础设施**。
- **趋势**：随技术进步和应用需求变化，持续发展与演进。

### 1.3 应用场景与需求

四大应用场景：

| 场景 | 要点 |
|------|------|
| **大数据存储** | 处理海量数据，适用于大数据分析与处理 |
| **云存储** | 提供可扩展、可靠、安全的云存储服务，满足企业/个人存储需求 |
| **备份与容灾** | 实现数据备份与容灾，保障数据安全性和可靠性 |
| **媒体和娱乐** | 处理大规模视频数据，适用于视频监控、视频点播等 |

记忆：大数据、云存储、备份容灾、媒体娱乐——「存、云、备、媒」。

## 二、分布式系统设计原则（Part 2）

### 2.1 分布式

三个要点：

| 要点 | 说明 |
|------|------|
| **分布式架构** | 采用**去中心化**架构，数据分散存储在多个节点上，提高**可靠性**和**可扩展性** |
| **节点自治** | 每个节点有自治能力，能独立处理请求和进行数据管理，**降低单点故障**风险 |
| **负载均衡** | 通过负载均衡技术，将请求均匀分配到各节点，确保**高可用性**和**性能** |

记忆：去中心化 + 节点自治 + 负载均衡 → 可靠、可扩展、高可用、抗单点。

### 2.2 可扩展

三种扩展方式：

| # | 方式 | 说明 |
|---|------|------|
| 01 | **横向扩展（Scale-Out）** | 增加**节点数量**扩展存储和计算能力，满足增长的数据需求 |
| 02 | **纵向扩展（Scale-Up）** | 提升**单个节点**性能（更强硬件 / 优化算法），提高整体性能 |
| 03 | **弹性伸缩（Elastic）** | 根据实际需求**动态调整**节点数量，实现资源合理分配与高效利用 |

对比记忆：
- 横向 = 加机器（节点数 ↑）
- 纵向 = 升机器（单机性能 ↑）
- 弹性 = 按需动态加减

配图要点：分布式数据库中数据先 **分片（partition1/2/3）**，每个分片再配 **副本（replication）**，分片+副本共同支撑可扩展与高可用。
