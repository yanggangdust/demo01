## 一、引言与基本概念（Part 1）

### 1.1 定义与特点
> 待补充：分布式文件系统的定义、核心特点（透明性/可扩展/高可用/容错/共享等）、与单机/集中式文件系统的区别。

### 1.2 发展历程及现状

#### 发展历程
- **早期**：分布式文件系统主要关注**高可用性**和**可扩展的存储服务**。
- **现代**：随互联网和云计算快速发展，转向**数据处理与分析能力**，并注重**与其他大数据技术的融合**。
- 演进主线：从「单纯存储」→「存储 + 处理/分析 + 大数据融合」。

#### 现状
- **应用领域**：云计算、大数据处理、高性能计算（HPC）等。
- **定位**：构建大规模数据存储与处理系统的**重要基础设施**。
- **趋势**：随技术进步和应用需求变化，持续发展与演进。

### 1.3 应用场景与需求

四大应用场景：

| 场景 | 要点 |
|------|------|
| **大数据存储** | 处理海量数据，适用于大数据分析与处理 |
| **云存储** | 提供可扩展、可靠、安全的云存储服务，满足企业/个人存储需求 |
| **备份与容灾** | 实现数据备份与容灾，保障数据安全性和可靠性 |
| **媒体和娱乐** | 处理大规模视频数据，适用于视频监控、视频点播等 |

记忆：大数据、云存储、备份容灾、媒体娱乐——「存、云、备、媒」。

## 二、分布式系统设计原则（Part 2）

### 2.1 分布式

三个要点：

| 要点 | 说明 |
|------|------|
| **分布式架构** | 采用**去中心化**架构，数据分散存储在多个节点上，提高**可靠性**和**可扩展性** |
| **节点自治** | 每个节点有自治能力，能独立处理请求和进行数据管理，**降低单点故障**风险 |
| **负载均衡** | 通过负载均衡技术，将请求均匀分配到各节点，确保**高可用性**和**性能** |

记忆：去中心化 + 节点自治 + 负载均衡 → 可靠、可扩展、高可用、抗单点。

### 2.2 可扩展

三种扩展方式：

| # | 方式 | 说明 |
|---|------|------|
| 01 | **横向扩展（Scale-Out）** | 增加**节点数量**扩展存储和计算能力，满足增长的数据需求 |
| 02 | **纵向扩展（Scale-Up）** | 提升**单个节点**性能（更强硬件 / 优化算法），提高整体性能 |
| 03 | **弹性伸缩（Elastic）** | 根据实际需求**动态调整**节点数量，实现资源合理分配与高效利用 |

对比记忆：
- 横向 = 加机器（节点数 ↑）
- 纵向 = 升机器（单机性能 ↑）
- 弹性 = 按需动态加减

配图要点：分布式数据库中数据先 **分片（partition1/2/3）**，每个分片再配 **副本（replication）**，分片+副本共同支撑可扩展与高可用。

### 2.3 数据复制

复制模型（配图）：**A 地域主盘（ESSD）** → **异步复制** → **B 地域从盘（ESSD）**；故障时可**故障切换 + 数据恢复**（从盘→主盘）。

三个核心原理：

| 原理 | 说明 |
|------|------|
| **延迟复制** | 数据写入主站点后**不立即**复制到从站点，而是**经过一定时间延迟**后再复制 |
| **写入确认** | 主站点收到写请求后，先确认数据**已成功写入本地存储**，再**异步复制**到从站点 |
| **最终一致性** | 基于异步复制，通过特定机制保证一段时间后**所有数据达到一致状态** |

要点记忆：异步复制 → 写本地先确认 → 延迟同步 → 最终一致（非强一致）。

### 2.4 数据分片

配图：原始数据 → **分片1 / 分片2 / 分片3 / 分片n** → 每个分片配多个 **副本**。

四个要点：

| 要点 | 说明 |
|------|------|
| **文件分割** | 用户上传文件时，系统先把文件切成多个**固定大小或动态大小**的分片；分片大小可按系统配置和存储需求调整 |
| **分片存储** | 分片分配到**不同物理节点**存储；节点间通过网络通信，共同维护整个文件系统的**完整性和可用性** |
| **分片与复制的关系** | 两者紧密相关：海量数据靠**数据分片**实现**水平扩展**，靠**数据复制**保证**高可用** |
| **复制提升读效率** | 复制还能提升读效率：客户端可从**物理更近的副本**读取，既提高读**并发**，又提高单次读**速度** |

记忆：分片 = 拆开分散存（扩容）；副本 = 多拷贝（高可用 + 读加速）。两者配合：分片解决容量/扩展，副本解决可靠/读性能。

#### 2.4.1 一致性哈希（常考点）

**解决的问题**：增删节点时缓存命中率大幅下降。

**算法**：
- 把整个哈希值空间组织成一个**虚拟圆环**（哈希环），环顶标 $0/2^{32}$。
- 节点的 **IP/主机名** 用哈希函数映射到环上。
- 存某个 **Key** 时：对 Key 用同一哈希函数找到环上位置，然后**顺时针走**，遇到的**第一个节点**就是目标节点。

**示例（配图）**：
- Key1、Key2 → Node1
- Key3、Key4 → Node2
- Key5 → Node3
- Key6 → Node4

**增删节点的影响**：
- 在 Node1 和 Node2 之间**加 Node5**：原本命中 Node2 的 **Key3** 改命中 Node5，其余 Key 不变。
- **删 Node3**：只有 **Key5** 受影响。
- **结论**：增删节点时只有**少量 Key 漂移**到别的节点，大多数 Key 映射不变，命中率不会明显下降。

易考点：一致性哈希核心优势 = **增删节点只影响相邻段少量 Key**，避免全局重新哈希。

#### 2.4.2 范围分片（Range Sharding）

**机制**：按 Key 的**区间**划分分片，用「分片 Map 表」记录 **Low Key → Machine** 的映射。
- 配图示例：banana、car → machine1；dark → machine2；zoo → machine3。

**常见场景**：按**时间区间**或 **ID 区间**分片。
- 时间：按天/月分到不同库。
- ID：1–9999 → 第一个库，10000–20000 → 第二个库，依此类推。

**优点**：
1. **单表大小可控**。
2. **易水平扩展**：加新节点只需为新区间加节点，**不用迁移已有分片数据**。
3. **范围查询高效**：按分片字段查询时，连续分片可快速定位，**避免跨分片查询**的性能问题。

**缺点**：
1. **热点数据瓶颈**：连续分片易产生「热点区间」。例如按时间分片，**近期数据所在分片读写频繁**，历史数据分片却基本闲置。

易考点：范围分片优 = 范围查询快、扩容不迁数据；缺 = 热点倾斜。常与哈希分片对比（哈希分片打散均匀但范围查询差）。

### 2.5 副本管理

#### 2.5.1 纠删码（Erasure Coding）

**配图流程**：文件切片成 4 个数据块 **A/B/C/D** → 纠删生成 2 个校验块 **P/Q**（即 **4+2** 配置）→ 分布到 3 节点集群：
- Node1：A、C
- Node2：P、D
- Node3：B、Q

**基本原理**：
- **冗余**：$k$ 个等大数据块 + $m$ 个校验块；只要丢失的块数 **不超过 $m$**（共 $k+m$ 块中任意 $m$ 块丢失），原始数据仍可恢复。
- **算法**：校验块用特定算法计算，如基于 **Vandermonde 矩阵**的 **Reed-Solomon 算法**。
- **恢复**：数据块或校验块丢失时，通过解 $n$ 元线性方程组恢复（$n = k+m$）。

**实现方式（对应 RAID）**：
| 模式 | 对应 RAID | 校验块数 | 可容忍丢失 |
|------|-----------|----------|------------|
| $k+1$ | **RAID-5** | 1 个 | 丢失 **1 块**可恢复 |
| $k+2$ | **RAID-6** | 2 个 | 丢失 **2 块**可恢复 |

易考点：纠删码 = $k$ 数据 + $m$ 校验，可恢复 $m$ 块丢失；RAID-5≈$k+1$，RAID-6≈$k+2$。相比多副本更省存储空间。
