# 防火墙考试考点（周四复习）

按用户发来的思维导图整理。复习时优先按本 skill 内容回答；可默写、对比、出题抽问。

## 一、防火墙基本理论知识

### 1. 定义与定位

- 防火墙是部署在**内网与外网边界**的防护设备。
- 核心作用：按安全策略控制进出流量，隔离不同信任级别网络。

### 2. 为什么需要防火墙

- 互联网固有特点：开放性、互联互通 → 易暴露。
- 典型风险：非法访问、数据篡改、越权渗透等。

### 3. 防火墙演进

发展脉络（由简到综）：

1. **包过滤（Packet Filtering）**
2. **应用层代理（Application Layer Proxy）**
3. **状态检测（Stateful Inspection）**
4. **统一威胁管理 UTM（Unified Threat Management）**

### 4. 关键技术

#### 包过滤（包过滤 / Packet Filtering）

- 检查字段：源/目的 IP、协议类型、TCP/UDP 端口等。
- 特点：基于单包五元组类信息做允许/拒绝；实现简单，对会话上下文感知弱。

#### 代理技术（应用代理）

- 防火墙作为通信双方的**中间人/中介**。
- 客户端与服务器不直连，由代理代为转发，可做应用层控制。

#### 状态检测技术（Stateful Inspection）

- 不只看单个包，还跟踪**活动连接状态**。
- 关注：TCP 会话状态、上下文信息等。
- 相对纯包过滤：更懂连接是否合法建立/进行中。

### 5. 功能介绍

#### 带宽管理

- 流量识别、控制、隔离、优化等。

#### 深度内容检测

- 可覆盖：
  - 应用层：HTTP、FTP、SMTP 等
  - 传输层
  - 网络层

#### NAT（网络地址转换）

- 防火墙的核心能力之一（详见第二节 NAT 类型）。

### 6. 防火墙 vs 路由器（易考点）

| 对比项 | 防火墙 | 路由器 |
|--------|--------|--------|
| 主要目的 | **安全防护**、策略控制 | **路由转发**、网络互通 |
| 关注点 | 安全域、访问控制、威胁防护 | 路径选择、可达性 |

## 二、常用防火墙工作模式与基础配置

### 1. 工作模式

| 模式 | 要点 |
|------|------|
| **路由模式** | 防火墙充当路由器/网关，三层转发，接口通常有 IP |
| **透明模式** | 对网络“不可见”，类似二层桥接，部署时少改原有拓扑 |
| **混合模式** | 路由 + 透明等能力组合使用 |

### 2. NAT 类型（速记表）

| 类型 | 用途 | 典型场景 |
|------|------|----------|
| **目的 NAT（DNAT）** | 公网 IP/端口映射到内网私网服务器 | 发布 Web 等对外服务 |
| **源 NAT（SNAT）** | 内网私网地址访问外网时换成公网地址 | 内网用户上网 |
| **双向 NAT** | 同时做源 NAT + 目的 NAT | 内外都能用公网 IP 访问内网服务器等 |

### 3. 防火墙基础配置详解（第二张导图 · 必背）

来源：《防火墙基础配置介绍》。考试常考「改哪个地址、流量两步、示例 IP」。

#### 3.1 目的地址转换（DNAT）

- **用途**：把内网服务端口发布到公网，公网用户用公网 IP 访问内网服务器。
- **原理**：单向地址转换，主要改数据包的**目的地址**。
- **拓扑记忆**：
  - Client：`1.1.1.1`
  - 云防火墙公网 IP：`2.2.2.2`，私网口：`172.16.0.2`
  - 业务云主机（虚机 IP）：`172.16.0.5`
- **流量走向**：
  1. Client 访问 `http://2.2.2.2:80` → 进入移动 VPC，平台转给云防火墙  
     - 源 IP：`1.1.1.1`  
     - 目的 IP：`2.2.2.2`
  2. 云防火墙匹配目的 NAT 规则，转发给业务云主机  
     - 源 IP：**仍为** `1.1.1.1`（不变）  
     - 目的 IP：**改为** `172.16.0.5`
- **一句话**：DNAT = **只改目的**，公网 IP → 内网服务器 IP。

#### 3.2 源地址转换（SNAT）

- **用途**：把内网私网地址转成防火墙外网公网地址，让内网用户上网。
- **原理**：也称「代理上网」；策略匹配后改**源 IP**。用于隐藏内网地址或共享公网 IP。
- **拓扑记忆**：
  - 业务云主机：`172.16.0.5`
  - 云防火墙公网 IP：`2.2.2.2`
  - 外网 Server：`1.1.1.1`
- **流量走向**：
  1. 业务主机访问 `http://1.1.1.1:80` → 送到云防火墙  
     - 源 IP：`172.16.0.5`  
     - 目的 IP：`1.1.1.1`
  2. 云防火墙匹配源 NAT 规则，转发给外网服务器  
     - 源 IP：**改为** `2.2.2.2`  
     - 目的 IP：**仍为** `1.1.1.1`（不变）
- **一句话**：SNAT = **只改源**，内网私网 → 公网 IP 再出去。

#### 3.3 双向地址转换（双向 NAT）

- **用途**：发布服务器；把内网服务端口映射到公网，使**外网和内网用户都能通过公网 IP 访问内网服务器**。
- **原理**：同一条策略里，**源地址和目的地址同时转换**。
- **拓扑记忆**：
  - Host：`172.16.0.3`
  - 云防火墙公网：`2.2.2.2`，私网口：`172.16.0.2`
  - 业务云主机：`172.16.0.4`
- **流量走向**：
  1. Host 访问 `http://2.2.2.2:80` → 送到云防火墙  
     - 源 IP：`172.16.0.3`  
     - 目的 IP：`2.2.2.2`
  2. 云防火墙匹配双向 NAT  
     - 源 IP：**改为** `172.16.0.2`（防火墙私网口）  
     - 目的 IP：**改为** `172.16.0.4`（业务主机）
- **一句话**：双向 NAT = **源和目的都改**（SNAT + DNAT 同策略）。

#### 3.4 三种 NAT 对比（易混）

| | 改源？ | 改目的？ | 典型方向 |
|--|--------|----------|----------|
| DNAT | 否 | 是 | 外 → 内（发布服务） |
| SNAT | 是 | 否 | 内 → 外（上网） |
| 双向 NAT | 是 | 是 | 用公网 IP 访问内网服（含内网侧访问） |

#### 3.5 访问控制策略

- **描述**：类似交换机 ACL，按策略动作拦截或放行流量。
- **原理**：比普通 ACL 更精细；可禁上网或禁特定应用。匹配可基于 IP、端口、服务，或应用特征（如视频类 App）。动作含：阻断、放行、黑白名单等。
- **使用场景**：对企业用户行为精细管控（HTTP、FTP、IM、各类软件工具）；可按**用户身份**、**时间段**做差异化权限。
- **与第一节「匹配要素」对照**：源/目的安全域、源/目的 IP、服务/协议、时间段、动作 permit/deny。

原则记忆：域间默认不互通，靠策略显式放行；匹配顺序与默认动作是常考细节（复习时按教材补充）。
## 三、安全域划分

### 1. 概念与规则

- **安全域**：按安全需求与**信任级别**划分的逻辑区域。
- 同域通常信任度相近；跨域流量必须经防火墙策略控制。

### 2. 按业务/性能等维度划分（示例）

| 域类型 | 说明 |
|--------|------|
| **管理域** | 管理流量、管理组件 |
| **业务域** | 应用服务器、云资源等业务系统 |

（教材若还有其他域名，以课堂材料为准，可再追加进本 skill。）

### 3. 移动云安全域案例（架构记忆点）

常见分区与角色：

- **CORE 区**：核心汇聚/连接中枢
- **DMZ（非军事化区）**：对外服务缓冲区（如 Web 服务器），隔离内外
- **Untrust 区**：不可信外网（Internet）
- 区间通过 **FW（防火墙）**、**SW（交换机）** 连接与隔离

记忆口诀方向：外网（Untrust）→ FW → DMZ（对外服务）→ 更可信内网/CORE；跨区必过防火墙策略。
