### 1.2 中国移动助力国家数字经济发展

**顶部概述（课件）**

中国移动发布 **"5G+AICDE"** 计划，以 **5G** 发展为契机，与**云计算、物联网、人工智能**等信息技术深度融合，打造**泛在智能基础设施**。**移动云**是 **5G+ 计划**重要组成部分。

**5G+AICDE 构成（泛在智能基础设施）**

| 字母 | 英文 | 中文 |
|------|------|------|
| **5G** | 5G | 第五代移动通信 |
| **A** | AI | **人工智能** |
| **I** | IoT | **物联网** |
| **C** | Cloud | **云计算** |
| **D** | Big Data | **大数据** |
| **E** | Edge Cloud | **边缘云** |

**速记口诀**

> 5G + **A**I **I**oT **C**loud **D**ata **E**dge

**三大战略支柱（三融）**

| 支柱 | 名称 | 含义 |
|------|------|------|
| **融合** | 云智/云网/云边/云数 | **云智、云网、云边、云数**融合，强化协同效应 |
| **融通** | 开放生态 | 构建**开放生态系统**，实现**能力和要素**整合 |
| **融智** | 智能运维 | **集中化、智能化**打造高效**运营运维**体系 |

**四融详解（融合）**

| 融合类型 | 含义 |

| **云边融合** | 云 + 边缘计算 |

### 1.4 移动云发展历程

**顶部概述（课件）**

自第一行代码诞生以来，移动云已走过**十余年**历程。从诞生之初就怀揣**"建云为国"**的志向，紧跟产业政策，积极创新，已成长为推动中国云计算产业发展的重要力量。

**五阶段发展曲线**

| 阶段 | 时期 | 阶段标签 | 关键词 |
|------|------|---------|--------|
| 1 | **2007~2013** | 起步探索 | 初始建设、探索阶段 |
| 2 | **2014~2019** | **提质**，内外部**规模化商用** | 苏州研发中心、规模化 |
| 3 | **2019** | **云改** | 云能力中心、管战建协同 |
| 4 | **2020~2022** | **腾飞**，关键核心**技术可控** | 国内**第一阵营** |
| 5 | **2023~** | **赋能**，云向**算力网络**演进 | 世界一流云服务商 |

**关键里程碑**

| 时间 | 事件 | 要点 |
|------|------|------|

| **2019 年** | **"云改"**拉开序幕 | 在苏州研发中心基础上挂牌成立**中国移动云能力中心**；**管战建**协同发力 |

### 1.5 移动云顶层设计

**顶部概述（课件）**

围绕移动云，中国移动构建了**"管战建"一体化协同**的组织体系，通过整合**总部、省公司、产研院和专业公司**的分类资源，实现**渠道、网络、客户、技术**等在云领域的**力出一孔**；在"管战建"模式牵引下，集团内优势资源向移动云**快速聚焦**，加速移动云成为**一流云服务商**。

**组织架构（管战建 + 研）**

```
              集团总部（管）
         资源统筹调度 / 政策管理支撑
                    │
         ┌──────────┼──────────┐
         │   管战建协同          │
    省公司（战）  云能力中心（建）  产研院/专业公司（研）
         └──────────┼──────────┘
                    │
              资源聚焦 → 移动云
```

**四大主体及职责**

| 主体 | 角色 | 简称 | 职责 |
|------|------|------|------|
| **集团总部** | 管 | 管 | **资源统筹调度**、**政策管理支撑** |
| **省公司** | 战 | 战 | 一线**作战**/销售落地 |
| **云能力中心** | 建 | 建 | **建设**移动云核心能力（图中绿色节点） |
| **产研院 / 专业公司** | 研 | 研 | **研发**与专业技术支撑 |

**协同关系（连线标注）**

| 协同路径 | 关系类型 | 具体内容 |
|---------|---------|---------|
| 省公司 ↔ 云能力中心 | **战建协同** | **销售支撑**、**资源支撑** |
| 云能力中心 ↔ 产研院/专业公司 | **建研协同** | **技术支撑**、**产品支撑** |
| 四者交汇 | **管战建协同** | 总部统筹下的整体协同 |

**核心机制**

| 机制 | 含义 |
|------|------|
| **力出一孔** | 渠道、网络、客户、技术等资源**统一聚焦**云领域 |
| **资源聚焦** | 集团优势资源向**移动云**集中（图示大箭头） |
| **管战建一体化** | 管理（总部）+ 作战（省公司）+ 建设（云能力中心）协同 |

**易考点**

- 顶层设计核心 = **"管战建"一体化协同**组织体系
- 四大主体：**总部（管）+ 省公司（战）+ 云能力中心（建）+ 产研院/专业公司（研）**
- **管**职责：资源统筹调度 + 政策管理支撑
- **战建协同**：销售支撑 + 资源支撑（省公司 ↔ 云能力中心）
- **建研协同**：技术支撑 + 产品支撑（云能力中心 ↔ 产研院/专业公司）
- 核心目标：**力出一孔** → **资源聚焦** → 移动云
- 与 1.4 呼应：2019 **管战建**协同发力
- 易错点：**云能力中心**是"建"（非"管"）；**省公司**是"战"（非"建"）；还有**研**（产研院/专业公司），共四主体

|------|------|------|
| 1 | **超大规模** | 支持 **50×2000** 规模；多集群调度 **10 万+（10W+）节点** |
| 2 | **业务透明** | 智能透明调度；多集群分布对**业务完全透明** |
| 3 | **超低延迟** | 云原生分布式网关 + 智能 DNS；流量转发性能损耗 **< 10ms** |
| 4 | **动态切流** | 基于 **10+ 因子**（集群负载/时延/地域等）；动态切换应用流量，保障稳定性 |

**算网原生 vs 分布式云原生（阶段 4 vs 3）**

| 对比 | 分布式云原生 | 算网原生 |
|------|------------|---------|
| 顶层 | 分布式调度/流量/数据 | **算力封装 + 算力感知** |
| 核心 | 分布式集群管理 | **算网融合编排调度** |
| 网络 | — | **分布式网络管理** |

**易考点**

- 云原生四阶段 = **容器云 → 云原生 Stack → 分布式云原生 → 算网原生**
- 方法论 = **E-CNA**；核心 = **动态分布式编排调度 + 跨域服务治理**
- 白皮书：**2022.7 解读 / 2022.8 发布**
- 四大特性：**超大规模（10W+节点）/ 业务透明 / 超低延迟（<10ms）/ 动态切流（10+因子）**
- 算网原生核心 = **算网融合编排调度** + **算力封装/感知**
- 与 1.6 呼应：**"云"向"算"**演进 → **算网原生**
- 易错点：最高阶段是**算网原生**（非分布式云原生）；10W+ = **10 万+节点**；延迟损耗 **<10ms**（非 <5ms）

### 2.6 移动云流淌着"内生安全"的血液

**核心概念：** **内生安全**——安全能力内嵌于云架构全层级，非外挂式防护。

#### 三层安全架构（中心图示，自上而下）

| 层级 | 名称 | 能力 | 组件 |
|------|------|------|------|
| **边界** | 近源清洗 | 流量防御/检测 | 流量防御、漏洞攻击防御、流量检测；网络检测防御节点（路由器/防火墙） |
| **内网** | 南北向+东西向 | 域间隔离 | **管理域**（DLP）、**共享 POD**（VPC）、**业务 POD**（蜜罐） |
| **主机** | 物理机→虚拟机→容器 | 主机级防护 | 平台应用 + 客户应用；账号安全/漏洞攻击防御/文件完整性防护 |

**主机嵌套结构**

```
物理机 → 虚拟机 → 容器
              ├── 平台应用
              └── 客户应用
         （账号安全 / 漏洞防御 / 文件完整性）
```

#### 网络安全管理平台（左侧）

资产清点 / 代码安全 / 情报管理 / 漏洞管理 / 内容安全 / 安全测试 / 事件管理 / 安全审计

#### 组件与工具映射（右侧）

| **漏洞攻击防御** | 系统/应用漏洞 | **WAF、IPS** |
| **内网攻击防御** | 东西向攻击、越权访问 | **蜜罐、UTS**（管理域）、防火墙、**VPC** |
| **数据保护** | 数据泄露 | **DLP** |
| **账号安全防护** | 暴力破解 | **云安全中心** |

云安全中心 / 态势感知 / 容器安全 / 数据库安全 / 密钥管理 / 数据库审计 / 网页防篡改 / 日志审计

| **每日抵御攻击** | **3.3 亿次**（33000 万次） |

#### 内生安全四大原则（底部，四个"全"）

| 原则 | 含义 |
|------|------|
| **全业务场景"不可见"** | 业务场景安全隔离/隐身 |
| **全网络流量"不可读"** | 流量加密/不可窃读 |
| **全访问请求"强授权"** | 访问须强认证授权 |
| **全用户行为"可追溯"** | 行为全程可审计追溯 |

**速记口诀**

> 不可见 / 不可读 / 强授权 / 可追溯

**易考点**

- 核心理念 = **内生安全**（内嵌于架构，非外挂）
- 三层架构 = **边界（近源清洗）/ 内网（管理域·共享POD·业务POD）/ 主机（物理机→VM→容器）**
- 内网三域：**管理域（DLP）/ 共享 POD（VPC）/ 业务 POD（蜜罐）**
- 工具映射：**DDoS→近源清洗 / 漏洞→WAF+IPS / 内网→蜜罐+VPC / 数据→DLP / 账号→云安全中心**
- 性能：**95 亿病毒库 / 600G 吞吐 / 500 万次·秒 CC / 3.3 亿次·日**
- 四原则 = **不可见 + 不可读 + 强授权 + 可追溯**
- 与 5.4（问题分析课）**黑色思考帽**不同——本节是移动云**内生安全体系**
- 易错点：**近源清洗**在**边界层**；**DLP**在**管理域**；**蜜罐**在**业务 POD**
