# 抬杠克星 · 产品方案需求评审

> 评审对象：`docs/抬杠克星-产品方案.md`（保留版）  
> 评审依据：职场表达/沟通技能市场与用户痛点调研（组织侧市场、中文职场内容、现有工具与培训失效研究）  
> 结论摘要：**需求真实；方案主航道正确；建议收紧「学以致用」验收与首屏承诺，补强迁移闭环，暂不扩口才/语音。**

---

## 0. 总评

| 维度 | 评级 | 说明 |
|------|------|------|
| 需求真实性 | ★★★★★ | 「一问就倒 / 结构抗压」是真实高频痛点，不是伪需求 |
| 痛点对齐 | ★★★★★ | 定位、关卡拆解、陷阱类型与用户抱怨高度同构 |
| 形态合理性 | ★★★★☆ | 游戏化刻意练习，对准培训失效的核心（缺练习、缺反馈、难坚持） |
| 差异化 | ★★★★☆ | 相对口才课 / AI 陪练 / 脑图代写，切口更窄更硬 |
| MVP 可落地性 | ★★★★☆ | 规则、地图、计分、题库清单已齐；内容扩写是主风险 |
| 效果闭环 | ★★★☆☆ | 成功标准偏产品过程指标；「练完能不能用」验收偏弱 |
| 命名风险 | ★★★☆☆ | 「抬杠」好玩但易误读；方案已意识到，仍需首页强校正 |

**一句话**：可以按本方案进入 MVP 开发；评审不推翻方向，只要求把「用户真正想带走的能力」写进验收与首屏，并守住不做口才/LLM 批改的边界。

## 1. 用户需求画像（评审参照）

调研收敛出的真实需求不是「能说会道」，而是：

> 开会、解释、拒绝时心里有货，一被追问就散；希望结构抗压，显得靠谱。

| 用户嘴上说的 | 真正想解决的 | 方案对应 |
|--------------|--------------|----------|
| 表达力差 / 不会说话 | 开口先有硬结论 | 「先甩一句」 |
| 汇报被追问懵 | 层次不乱、细节不上抬 | 「细节给我下去」 |
| 会上被拆 / 讲不清 | 理由不打架（MECE） | 「别给抬杠留缝」 |
| 周报/复盘像流水账 | 口语收成能出门的结构 | 「说硬了再出门」 |
| 想提升口才 | **不该接**：流利、情商、辩赢 | §2「别吹过头」已正确拒绝 |

市场侧信号：沟通技能培训市场持续增长；无效沟通有明确组织成本；中文职场内容反复出现「所以呢 / 结论先行」。现有方案弱在：**知行鸿沟、一次课难固化、练习压力不够真、工具代劳结构**。

→ 方案用「碎片刷关 + 先挨刀再炼硬 + 标准答案拼图」去填这个缺口，方向成立。

## 2. 方案与需求的对齐：建议保留

### 2.1 定位公式（§2）——强烈保留

「练结构、不好被问倒 / 不教抬杠」与调研结论一致。  
「能给 / 不承诺」边界写得好，应成为对外文案与成功标准的硬约束。

### 2.2 四种关卡拆解（§1 / §3.1）——强烈保留

把金字塔拆成四个可练动作，比笼统「学金字塔」更可验收。  
陷阱五类（过程/情绪当结论、细节上抬、伪 MECE、答错题）直接对应用户被追问时的典型翻车。

### 2.3 单关「挨刀 → 炼硬 → 审讯」（§3.1）——强烈保留

培训研究强调：要改变行为需要 **排练 + 反馈 + 间隔**，而不是听课。  
冷开场用 `softReply` 复现「软回答被追问」，是低成本模拟压力的好设计；比纯做分类题更贴近痛点。

### 2.4 职场主线 + 生活平行线（§3.0）——保留并强调价值

调研指出技能迁移难（near transfer → far transfer）。  
同周生活关做同构迁移，是方案相对「只会练职场汇报脚本」的差异点，**不要在 MVP 为了省题砍掉生活关**；可接受生活关文案略薄，但槽位比例（10:6）应维持。

### 2.5 不做 LLM 批改 / 不做语音（§8）——MVP 强烈保留

AI 口才 App 已在「开口、语速、自信」赛道；方案切口是 **结构对错与追问缝**。  
预置金标 + 陷阱标记，反馈可解释、可稳定，比早期 LLM 批改更适合验证「结构肌肉」假设。

### 2.6 再闯换题 + 每日一练（§5.1 / §4.3）——保留

对准「间隔练习 / 防原题重刷」；与培训失效研究中的 spaced practice 一致。

## 3. 风险与错位：需要补强

### 3.1 【P0】首屏与命名的误读风险

**问题**：调研里用户会搜「口才 / 表达力」；产品名含「抬杠」，容易被理解成抬杠技巧或斗嘴游戏。  
方案 §1 已要求对外用「会被追问」，但成功标准 §9 只写「打开首页就懂」，**缺可操作的验收文案**。

**建议**：

- 首页必须同时出现：主名 + 副标题 + 一句话定位（「练的不是口才，是结构站得住」）。  
- 首屏 CTA 用「开始把话说硬 / 开始练结构」，避免「开始抬杠」。  
- 用 5 人走廊测试验收：去掉导航后，陌生人是否仍能说出「这是练汇报结构的」，而不是「斗嘴游戏」。

### 3.2 【P0】效果闭环偏弱——用户要带走的能力未进硬验收

**问题**：§9「效果愿望」写了「能写出结论句 + 3 条不打架的理由」，但标注「验收方式另定」，容易在开发中被挤掉。  
调研表明：enjoyment ≠ transfer；用户要的是会后还能用。

**建议**：把下列至少一项升为 MVP 验收（可极简）：

1. **通关小考（推荐）**：通关或第 8 关后，给一道未见过的开放场景，限时写出「结论 + ≤3 理由」；人工或对照 rubric 判定是否达标（不要求 AI）。  
2. **迁移提示可操作化**：结算页的 `transferTip` 必须是「下次开口可套用的句式」，禁止空泛鸡汤。  
3. **会前热身入口**：首页次要入口「开会前 3 分钟」——抽 1 道 conclude/export，强化「加分场景」真实存在。

### 3.3 【P1】「拼图过关」与「真实开口」之间的鸿沟

**问题**：MVP 是选句/拖拽/分桶，不强制用户自己生成结论句。  
调研痛点之一是「不会写一句可决策的结论」——识别金标 ≠ 会生成。

**建议（不推翻 MVP）**：

- 在结算 3 星或通关小考中，加一步 **「用自己的话重写结论」**（本地文本框即可，可不自动批改；可提供金标对照自检）。  
- 或在「说硬了再出门」关增加「先选后排序」之外的 **空槽填写（可选）**。  
- 文档中明确：MVP 验证的是「结构判别力」；V1.1 再验证「结构生成力」。

### 3.4 【P1】剧情沉浸 vs 工具感的平衡

**问题**：用户主要诉求是工具（碎片练结构）；连续发布周剧情能提高粘性，也可能让「急着用」的人觉得绕。  
方案「主要刷关 / 加分会前热身」正确，但信息架构里每日一练偏后。

**建议**：

- 首页双路径并重：**开始练（主线）** / **每日一练（弱项）**；通关前也显示每日一练。  
- 地图允许看到「本周故事」，但单关页前 3 秒必须先看到场景问句，避免剧情文压过练习任务。  
- 原理小屋可做，但不要挡在第 1 关之前。

### 3.5 【P1】题库扩写是最大交付风险

**问题**：§6.4 清单齐，但完整可玩卡组仅示范 M01–M03；A01–A16 与多数主线仍待扩写。  
再闯「一半槽位换新」依赖池深；池不够则 §5.1 / §9 承诺落空。

**建议**：

- 开发 checklist 把「主线 16 题 units 写满」列为 **上线门禁**；备选 16 题可分两批，但每种 `type+diff+domain` 至少 2 题才能声称支持再闯。  
- 内容质量门禁：每题必须有 ≥1 个真陷阱、非弱智干扰；`followUpLines` 必须像真实追问。

### 3.6 【P2】竞品边界要写进方案，避免以后漂移

现有替代品大致三类：

| 竞品类 | 强项 | 方案应坚持的差异 |
|--------|------|------------------|
| 书课/企业培训 | 方法论完整 | 我们提供可重复的低成本练习，不是又一堂课 |
| 脑图/AI 写周报 | 代劳产出 | 我们练人的结构肌，不代写 |
| AI 口才陪练 | 开口、语音、自信 | 我们练「焊结论 / 堵缝」，默认不做语音 |

**建议**：在 §2 或 §8 增加「竞品不做清单」短表，防止后续把产品做成「又一个口才 App」。

### 3.7 【P2】支付改版主线的人群覆盖

**问题**：主线偏互联网/产研职场；痛点人群还包括人事、销售、基层执行等。  
MVP 用一条高密度因果链是对的，但生活关 + 备选题应覆盖更泛的「拒约 / 拍板 / 换工作」。

**建议**：MVP 不改主线；备选 A 组优先补「非产研也能代入」的场景（方案里 A06/A07/A09/A11/A12/A14 已有苗头，扩写时保质）。

## 4. 成功标准修订建议（§9）

| 原标准 | 评审意见 |
|--------|----------|
| 30 秒进第 1 关并提交 | 保留；作为激活指标 |
| 首页懂「不是教抬杠」 | 保留；补走廊测试或文案清单 |
| 职场关多于生活关 | 保留 |
| 断网可通关；每关有追问点 + 迁移提示 | 保留；迁移提示改为「可套用句式」 |
| 再闯一半槽位换题 | 保留；绑定题库池深门禁 |
| 效果愿望另定 | **改为 MVP 必做一项极简迁移验收**（见 §3.2） |

建议新增：

- **首周留存代理指标**：完成 ≥4 关的用户占比（验证「碎片刷关」是否成立）。  
- **3 星率监控**：若某关 3 星率 >70% 或 <15%，触发难度微调（对应 §10 第 6 步）。

## 5. 对实现顺序的微调建议（§10）

原顺序大体正确。建议微调优先级：

1. 脚手架 + 首页（含定位文案）+ 地图 + localStorage  
2. 四种关卡组件 + 陷阱结算（**表达架话术：焊死/堵缝**）  
3. **主线 16 题写满**（门禁）→ 再补备选至池深达标  
4. 抽题器 + 再闯换题  
5. 结算点评（追问点 + 可套用迁移句）+ 每日一练入口前移  
6. （可选但推荐）通关/中段「自写结论」自检或极简小考  
7. 动效与难度微调  

原理小屋可置于 5 之后，不阻断主线。

## 6. 评审决议

| 决议 | 内容 |
|------|------|
| **方向** | 通过。工具内核 + 游戏外壳，对准真实痛点。 |
| **MVP 范围** | 维持：本地网页、16 槽、四关型、预置题库、无登录/无 LLM 批改/无语音。 |
| **必须补的产品描述** | ① 首屏反误读文案验收 ② 效果迁移的一项硬验收 ③ 题库池深门禁 ④ 竞品不做边界 |
| **明确不改** | 不教抬杠；不承诺辩赢/情商/流利；生活平行线不删；星级公式与线性解锁保持。 |
| **下一步** | 按修订后的 checklist 进入 `gang-buster` 落地；内容与工程并行，主线题写满优先于视觉打磨。 |
